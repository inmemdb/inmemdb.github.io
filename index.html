inMemDB

In-memory database for Go apps and standalone servers.

inMemDB can run inside your Go executable or as a local database server, giving services, CLIs, tests, and local-first tools fast structured storage.

Embed in Go Run the CLI
two ways to run Go + CLI 
# Embed in a Go application
go get github.com/inmemdb/inmemdb-go

package main

import (
    "context"

    "github.com/inmemdb/inmemdb-go"
)

func main() {
    ctx := context.Background()

    db, err := inmemdb.Open(ctx)
    if err != nil {
        panic(err)
    }
    defer db.Close()

    // Use through the Dalgo database API.
    _ = db
}

# Or run as a standalone server
go install github.com/inmemdb/inmemdb-cli@latest
inmemdb serve

Why inMemDB

Use inMemDB when your application needs temporary, fast data storage with a real database-shaped API, either in-process or over a local server boundary.

Embed it

Ship storage inside your Go binary and keep deployments simple.

Run it

Start a standalone server for local workflows and tools.

Open source first

Developed in public as part of the Dalgo database ecosystem.

Made to embed into Go executables

inMemDB is implemented in Go and designed to be linked directly into Go applications. It is a library you import, not another service to run.

  • In-process storage for services and command-line tools
  • Simple setup for integration tests and development fixtures
  • API exposed through a Dalgo adapter

Run it as a standalone server

The inMemDB CLI packages the same product idea as a runnable database process. Use it when a tool, integration, or development workflow wants a server instead of an embedded library.

CLI and server github.com/inmemdb/inmemdb-cli

Powered by Dalgo

The project exists to make the Dalgo adapter model easier to try, embed, and understand. If you can use inMemDB, you can see how Dalgo database implementations fit together.

Core library github.com/dal-go/dalgo
